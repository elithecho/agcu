## Interaction

| Command                        | Description                                |
| ------------------------------ | ------------------------------------------ |
| `agcu click [selector] -a App` | Click an element (AXPress, no focus steal) |
| `agcu type "text" -s @e3`      | Clear and type into a field (AXSetValue)   |
| `agcu type "text" -a App`      | Type into focused field (keyboard sim)     |
| `agcu key cmd+k -a Slack`      | Press a key or combo                       |
| `agcu scroll down -a Music`    | Scroll within an app                       |
| `agcu scroll-to @e42`          | Scroll element into view (headless)        |
| `agcu drag @e5 @e10 -a Finder` | Drag from one element to another           |

| `agcu screenshot -a App --path shot.png --grid`      | Add a coordinate grid (macOS)   |

### Screenshot coordinate grid

`--grid` is optional and off by default. On macOS, it overlays lines every
**100 absolute screen points**, with x labels across the top and y labels down the
left. Use those values directly with the existing coordinate click command:

```bash
agcu screenshot -a App --path shot.png --grid
agcu click -a App --x 400 --y 300
agcu screenshot -a App --path after.png --grid
```

`-a App` activates the app when clicking; it does **not** make coordinates
window-relative. A window captured at 2× Retina resolution with origin `(125, 80)`
places screen point `(400, 300)` at image pixel `(550, 440)`. Click using **400, 300**,
not the image pixels. The grid already accounts for window origin and image scale.
Image viewers may resize the screenshot; read the numeric labels instead of
assuming displayed pixels are click coordinates.

Without `-a`, `agcu screenshot --grid` captures only the main display. Omitting
`--path` keeps the existing auto-generated path. Plain screenshots remain unchanged.
Linux and Windows reject `--grid` with `action_not_supported`, without writing the
output file; omit the flag for a plain screenshot on those platforms.

Recapture after moving/resizing windows or changing display configuration. App
activation or UI changes can invalidate a target, so verify the result after clicking.
Coordinate clicks can move the mouse and steal focus. Capture/render/write failures
return a nonzero status and the existing JSON error envelope, never a successful
unannotated image. Check Screen Recording permission and window availability if
native capture fails; permissions are not granted automatically.

## Snapshot Options

```bash
agcu snapshot -a Calculator              # full tree
agcu snapshot -a Calculator -i           # interactive elements only
agcu snapshot -a Calculator -c           # compact (skip empty containers)
agcu snapshot -a Calculator -d 3         # limit depth
agcu snapshot -a Calculator -i -c -d 5   # combine options
```

| Option              | Description                                        |
| ------------------- | -------------------------------------------------- |
| `-a, --app`         | Target application                                 |
| `-i, --interactive` | Only interactive elements (buttons, inputs, links) |
| `-c, --compact`     | Remove empty structural elements                   |
| `-d, --depth`       | Limit tree depth                                   |

## Global Options

| Option              | Description                            |
| ------------------- | -------------------------------------- |
| `--human`           | Human-readable output                  |
| `--compact`         | Compact single-line JSON               |
| `--timeout <s>`     | Global timeout in seconds (default: 5) |
| `-v, --verbose`     | Debug traces                           |
| `--cdp`             | Force CDP mode for Electron apps       |
| `--cdp-port <port>` | Override CDP port                      |
| `--no-cdp`          | Disable CDP auto-detection             |
