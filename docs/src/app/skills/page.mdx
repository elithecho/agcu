The repository ships `skills/agcu/SKILL.md`. The **[skills.sh](https://skills.sh)**
CLI can install it from a local checkout without relying on a published npm CLI package.

## Install the skill

Run from the repository root after cloning `https://github.com/elithecho/agcu`:

```bash
npx skills add . --skill agcu -g
```

- `-g` installs globally (available in every project). Drop it to install into the current project's `.claude/skills/` only.
- Works with Claude Code, Cursor, Codex, Copilot, OpenCode, Cline, VS Code, and more. Pass `-a <agent>` to target one specifically, e.g. `-a claude-code` or `-a cursor`.

Once installed, the SKILL.md lives at:

```
~/.claude/skills/agcu/SKILL.md
```

Your agent loads it at session start. Any prompt like "open Music and play X" or "fill out this form" will route through `agcu` automatically.

## Skip the approval prompts

By default, Claude Code asks for approval on every `agcu` command. To run without prompts, use the built-in setup wizard:

```bash
agcu setup
```

Interactive menu:

```
› How should agcu run in Claude Code?
❯ Unsupervised
  Supervised
```

Picking **Unsupervised** writes `Bash(agcu *)` into your settings so every `agcu` subcommand auto-approves. **Supervised** keeps the default "ask every time" behavior.

### Non-interactive flags

For CI, scripts, or AI agents running setup themselves:

```bash
agcu setup --yes                              # unsupervised + global
agcu setup --mode unsupervised --scope project
agcu setup --mode supervised                  # no-op, explicit
```

| Flag      | Values                                             |
| --------- | -------------------------------------------------- |
| `--mode`  | `unsupervised`, `supervised`                       |
| `--scope` | `global`, `project`                                |
| `--yes`   | shorthand for `--mode unsupervised --scope global` |

**Scope:**

- `global` → `~/.claude/settings.json` (every project)
- `project` → `./.claude/settings.local.json` (this directory only)

Running `agcu setup` again is idempotent — it detects the existing rule and exits without changes.

## Manual config (alternative)

If you prefer to edit settings yourself, add this to `~/.claude/settings.json`:

```json
{
  "permissions": {
    "allow": ["Bash(agcu *)"]
  }
}
```

Same effect as `agcu setup --yes`.

## Update the skill

Installed skills are cached locally. After updating your checkout, reinstall the skill:

```bash
npx skills add . --skill agcu -g
```

Then fully quit and relaunch your agent — skills load at session start, running sessions keep the old version cached.

## Remove the skill

```bash
npx skills remove agcu -g -y
```
